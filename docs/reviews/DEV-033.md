# DEV-033 · 员工信息统一重构审查

- 日期：2026-10-16
- 范围：canonical字段复用、原子创建、XLSX preview/执行、目录/详情投影、授权与响应式布局

## 已关闭发现

1. 员工详情新增catalog读取后，metadata-only响应曾在并行请求中再次调用全量清空，从而可能竞态擦除已返回的catalog。刷新开始时已经销毁旧敏感状态；metadata分支现只删除不应存在的profile revision，不再破坏同一generation的新catalog。
2. 批量确认最初可能重新以顶部查看日期读取catalog，而不是消费preview冻结的revision。执行现直接使用preview返回的catalog/graph revision；服务端创建事务仍重新验证，变化时明确冲突并要求重新preview。
3. 既有主管最初按全局查看日期解析，会把员工入职日尚未有效或当时已退职的主管误配。目录查询现以每行`hire_date`为`as_of`，并以`Staff Code + hire_date`作为解析缓存键。
4. 批量创建body曾仅提交profile/lifecycle/Staff Code。现逐行提交已解析的employment、education及job assignment；直属主管仍在两端创建结果明确后由单一OP-ORG-10提交，保留原有部分成功和未知结果恢复语义。
5. 员工目录原先只显示少量组织字段。现从同日catalog父链派生BG/Division，完整显示用户样表中的人员业务列，保持服务端cursor分页和独立滚动容器。
6. 创建页面原说明仍声称任职、组织关系和学历以后维护；现改为一次完整初建，并将内部ID/revision收进折叠数据状态。薪资边界明确留在独立financial工作台。
7. 全量前端集成fixture最初未声明详情新增的catalog HTTP边界，导致身份与授权导航回归失败。fixture现只对白名单catalog GET返回明确DTO，其他意外HTTP仍失败；55项IdentityGate和82项Grant测试分别通过。
8. 功能/技术规范仍记载9列模板和最小初建。现更新为18列双语模板、完整canonical创建、按行有效日解析、目录/详情字段及Mermaid数据流；DEV-032明确标记字段范围已被DEV-033替代。
