# DEV-032 · 人员资料批量上传与模板审查

- 日期：2026-10-16
- 范围：模板与安全解析、预览释放、批量执行、主管解析、未知结果恢复、页面可用性

## 已关闭发现

1. 5xx/408创建与主管命令曾被当作明确失败；改为结果不确定，冻结并只重放原key/body。
2. 未知创建恢复曾使用最新graph；改为先按原命令冻结graph重放，再进行可变主管预检。
3. 无关失败行曾阻止未知行恢复；失败行不再参与后续预检。
4. 已完成主管命令可被新key重复；完成批次现为终态，只能明确开始下一批。
5. 主管目录只读取第一页；现跟随有界cursor最多100页，在同一graph revision内精确匹配全集团Staff Code。
6. 已确认创建但主管消失时曾可能改写成未创建失败；现以已确认employee ID保留人员并标记“主管待维护”，跨多次恢复不降级。
7. Preview替换可覆盖执行中状态；执行开始后锁定文件与preview，直到批次完成并明确开始下一批。
8. Preview曾省略英文姓名、联系方式和资料摘要；现确认前完整显示所有将持久化的profile字段。
9. HTTP 409曾一律显示Staff Code重复；改为不误导的“Staff Code已存在或组织版本已变化”。
10. XLSX column解析存在整数溢出风险；现先执行Excel最大列/行边界检查。
11. Shared-string可放大preview输出；每个输出字段按业务上限截断为不回显并返回`field_too_large`。
12. 大量空row/cell/XML node曾在业务行限制前物化；共同读取器现在XML token预检后才反序列化。
13. 唯一worksheet曾只按ZIP路径判断；现核对`workbook.xml`及relationship，拒绝额外/未声明工作表，并兼容package-relative与package-absolute合法target。
14. 功能数据流曾把结果不确定画成直接失败；Mermaid已区分暂停、原命令重放、主管待维护及后续人工查询。

## 结论

全部发现均已修正并有针对性回归；最终全量Go编译、相关Go行为测试、265项Web测试、production build与真实浏览器桌面/移动smoke通过。PostgreSQL仅因当前环境缺少`POSTGRES_TEST_DSN`未执行，不以SQLite结果冒充双数据库实测。
