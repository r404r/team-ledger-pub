# DEV-036 · 人员批量上传选件反馈验证

- 日期：2026-10-16
- 范围：人员批量XLSX选件交互、既有模板/preview API调用及真实页面反馈
- 数据变更：无schema、migration或API契约变更

## 根因与实装

- 后端上传API已经存在：`GET /api/v1/orgs/:org_id/employees/import-template`返回固定18列模板；`POST /api/v1/orgs/:org_id/employees/import-preview`完成有界解析、目录解析和只读预览；确认阶段仍复用既有逐行人员创建及主管关系命令。
- 原页面`chooseWorkbook()`只保存`File`并清空旧状态，选择文件不会调用preview；必须再次点击“校验并预览”，且选件后没有文件名或等待状态，用户观察为“没有效果”。
- 现页面在选择合法XLSX后立即显示文件名并调用一次preview。处理中显示上传状态；成功显示行数、逐行预览及错误；失败保留错误和“重新校验”；人员创建仍须单独明确确认。

## 自动验证

- `npm test`：11个test file、273项测试全部通过。新增组件回归直接选择文件，不点击第二个按钮，观察一次`POST .../employees/import-preview`、`File`请求体和可见预览。
- `npm run build`：`vue-tsc --noEmit`及Vite production build通过。
- `go test ./internal/httpapi -run '^TestAPIPersonnelImportTemplateAndPreviewAreAuthorizedAndReadOnly$/^sqlite$' -count=1`：通过；覆盖模板、preview授权和只读行为。
- `go test -run '^$' ./...`：23个Go package编译通过，9个package无测试。
- `go vet ./...`：通过。

## 真实路径验证

- 以production Docker镜像、SQLite、keyd及独立audit receiver启动隔离栈，在真实Chromium完成本地密码＋TOTP登录并进入人员资料页。
- 从运行中API实际下载模板，填写`SMOKE-001`及完整18列后在文件控件中选择；无需点击“校验并预览”，浏览器立即观察到唯一一次`POST /api/v1/orgs/:org_id/employees/import-preview`，HTTP 200。
- 页面显示文件名`dev036-personnel-filled.xlsx`、`1 行`、人员姓名“批量上传测试”及6项缺失目录code错误；“确认并批量创建”保持禁用。证明自动上传、业务错误预览和不自动创建同时成立。
- 隔离栈、命名volume、浏览器及临时Docker目录已清理；未接触既有部署数据。

## 结果语义

- 问题不是“批量上传API未实现”，而是前端选件事件未调用已经存在的preview API。
- 修复只改变何时触发只读preview及反馈文案；5 MiB/100行、CSRF、same-origin、权限、安全XLSX解析、零文件持久化、逐行创建幂等及主管关系提交边界不变。
