# DEV-037 · 安全审计可用性诊断与拒绝态验证

- 日期：2026-10-16
- 范围：P-SEC-02审计实现核对、权限/MFA拒绝态、审计路由step-up、本地密码＋TOTP设施可用性
- 数据变更：无schema或migration变更；既有部署直接使用新binary/web assets

## 实现核对

- 安全审计不是空壳：`GET /api/v1/audit-events`进入`internal/audit.Service.List`，以独立`audit.read / audit / security_administration`和近期MFA授权，返回脱敏metadata及签名cursor；主库事务同步写`audit_event`/outbox。
- Docker Compose包含独立`audit-forwarder`和append-only `audit-receiver`；forwarder以mTLS投递并验证签名receipt，receiver状态参与API ready。
- fresh local bootstrap的`bootstrap_policy.v1`有意只授OrgR/OrgW/PIIR/PIIW；不授`audit.read`或`access_grant.manage`。截图表示当前账号不满足独立授权或近期MFA，不表示API/receiver未实现。

## 修复

- `AuditPage`先验证session结构，再分别处理MFA过期、缺少`audit.read`、查询期间授权变化、会话失效和服务不可用；拒绝时清空结果、隐藏筛选工作台。MFA有效但无权限时不调用`/audit-events`。
- `/security/audit`进入Web canonical return allowlist，step-up action固定为`audit.read`；本地与OIDC均不再错误发送`pii.write`。
- local模式的`/session.identity_available`按内置密码/TOTP设施返回true，不再错误依赖OIDC verifier。
- step-up严格JSON shape接受local模式所需`current_password`和`totp_code`；真实local请求不再在identity service前被422拒绝。
- 未改变独立审计授权模型，也未把bootstrap账号自动升级为审计员。
