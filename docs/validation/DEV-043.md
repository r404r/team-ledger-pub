- 日期：2026-10-16

- 真实TLS PostgreSQL 17使用`sslmode=verify-full`及本次独立CA/server certificate；测试角色实查`rolsuper=false`、`rolbypassrls=false`。
- 全量命令：
  - `TEAMLEDGER_TEST_POSTGRES_DSN='postgres://…?sslmode=verify-full&sslrootcert=…' go test -p 1 ./...`
  - 结果：23个package通过，9个package无测试。
- `go vet ./...`通过。
- 永久回归覆盖两种后端的fresh v17、v16→v17、checksum/版本拒绝、关联唯一性、同事务失败回滚及既有账号不推断政策。

## Production Docker迁移

使用生产`Dockerfile`分别构建schema v16 fixture image和当前v17 image：

1. 空命名卷以当前image执行migrate两次，覆盖fresh安装和幂等重启。
2. 第二个空命名卷先以v16 image执行migrate，再以当前image执行两次，覆盖v16→v17及幂等重启。
3. 两个卷只读检查均为17条`schema_version`、最大版本17、backend=`sqlite`、`PRAGMA integrity_check=ok`，且均存在空的`staff_account_access`。

该production Docker smoke使用空v16 fixture，不冒充有数据保留证明；有数据、不自动推断及两后端约束由永久migration测试覆盖。README §1.9登记停写、备份、升级、ready核对及失败恢复边界。

## 权限边界

- Staff默认scope只含本人和当前有效administrative一层直属下属；同级、上级、二层下属、已结束/替换关系及已结束员工生命周期均拒绝。
- 员工读取包含metadata及PII；不包含修改、薪资、奖金或敏感导出。
- 面谈只包含metadata读取及OP-INT-02创建；状态转换、笔记、行动、评估和通用`interview.write`继续拒绝。
- `staff_default.v1`不是grant或delegable authority；非关联账号仍无默认业务权限。
