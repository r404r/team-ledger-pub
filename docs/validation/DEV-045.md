# DEV-045 · 人员XLSX日期兼容与错误透传验证

- 日期：2026-10-16
- 结论：SQLite/PostgreSQL真实API、parser、292项Web测试、production build及真实Chromium错误/成功preview均通过。

## 已确认根因

服务端会对字段错误返回HTTP 200、`rows/errors/row_count`，但当所有行的入职日均无效时不会读取目录，JSON因`omitempty`省略`catalog_revision/graph_revision`。旧页面把revision缺省一律改写成客户端503，丢弃服务端已有的`Employees!J行`错误。这不是文件没有上传，也不是API没有解析出数据。

## 修复契约

1. 仅当preview已有至少一个逐行错误且两个revision同时缺省时，页面接受该错误preview并保持创建按钮禁用；无错误preview仍必须有两个正revision。
2. 页面逐项显示`Employees!单元格 · 字段：原因`；真正5xx没有安全cell时显示request ID，不伪造位置。
3. 入职/退职日期接受四位年份的年在前`-`、`/`、`.`、中文年月日，以及年在后的月/日/年`-`、`/`、`.`文本，统一成`YYYY-MM-DD`。
4. 不存在日期分别返回J/O列`invalid_date`；退职日不晚于入职日返回O列`departure_not_after_hire`。
5. Excel numeric/date cell、公式、两位年份、时间/时区及混合分隔符保持拒绝；不猜测Excel 1900/1904日期系统。
6. 结构和逐行拒绝日志只含request ID、安全sheet/cell/row/field/code，不含单元格值或PII。
