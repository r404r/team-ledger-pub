# DEV-039 验证摘要 · 会话后台核对与文件上传连续性

- 日期：2026-10-16
- 结论：authenticated focus改为非破坏式后台核对；人员XLSX选择、在途preview和页面状态不再因文件选择器或窗口切回而丢失。

## 1. 失败复现

修复前新增consumer-visible回归用例并单独运行：选择`people.xlsx`、保持`POST /employees/import-preview`未决、触发`window.focus`。实测失败为identity state从`authenticated`切到`checking`，与用户截图一致；业务组件被卸载并取消在途文件预览。这证明问题位于共同身份生命周期处理，不是缺少批量上传API。

## 2. 自动验证

| 命令 | 结果 |
| --- | --- |
| `cd web && bun run test -- IdentityGate.test.ts` | 65/65通过；覆盖文件上传期间focus、重复focus合并、401/身份变化/竞态继续fail closed |
| `cd web && bun run test -- PersonnelImportPanel.test.ts` | 3/3通过；模板、preview及逐行创建行为保持 |
| `cd web && bun run build` | `vue-tsc --noEmit`及Vite production build通过；104 modules transformed |

仓库没有独立`typecheck` script；production build已先执行同一`vue-tsc --noEmit`门禁。

## 3. 真实浏览器

以production Vite产物和受控同源API边界运行真实Chromium（1440×1000）：

1. 打开人员资料并展开“批量上传人员”。
2. 上传`team-ledger-browser-people-2.xlsx`，让preview响应延迟1.8秒、下一次session响应延迟1.2秒。
3. preview未决时派发真实窗口focus事件。
4. 250ms观察：文件input仍存在；页面显示“正在上传并校验”；不存在“正在核对服务端会话”。
5. 延迟响应完成后观察“已校验 1 行”和预览员工“浏览器上传员工”。

该场景同时证明后台session核对没有卸载`PersonnelImportPanel`，也没有中止已发出的preview请求。

## 4. 安全边界

保留既有自动用例：初始checking期间的新拒绝结果可取代旧响应；内部路由/后台核对遇401销毁页面；身份主体、组织或auth epoch变化关闭消费者；网络/非成功响应进入不可用态。修复不延长session或MFA有效期。
