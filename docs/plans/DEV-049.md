# PLAN · DEV-049 · HOD Staff Code 复合格式与同批次顺序无关的上级解析

- 日期：2026-10-23
- 状态：实现与本地门禁通过；独立审查待后续审查阶段进行；最终候选门禁结果见[验证记录](../validation/DEV-049.md)
- 关联功能：F-ORG-001（OP-ORG-05人员批量导入与可编辑预览、OP-ORG-10主管关系写入）
- 目标：批量上传人员时，`HOD Staff Code`既可填纯工号也可填`<Staff Code>-<Staff Name>`；主管排在下属之后（含多层逆序链）仍可校验和提交。
- 既有环境：复用现有员工、identifier与reporting事实；不清库、不改既有migration，本任务无schema migration。

## 1. 已确认规则

1. 真实Staff Code不含连字符`-`。`HOD Staff Code`非空且含`-`时，取第一个`-`之前并trim为主管Staff Code（`002046-San Zhang`、`002046 - San Zhang` → `002046`）；空值保持为空，不含`-`的值原样处理。Staff Code自身列不做此提取。
2. `HOD Staff Code`填的是上级主管工号，允许留空。
3. 主管有效集合 = 现有员工Staff Code ∪ 本批次全部Staff Code，与行先后无关。同批次自我汇报、批次内闭环阻断。
4. 提交为两遍：同一事务内Pass 1按文件顺序创建全部员工并建立`staff_code → employee_id`映射；Pass 2用OP-ORG-10 reporting命令统一绑定，失败整批回滚。报错行号保持原文件行号。

## 2. 设计决定

| 决定 | 内容 |
| --- | --- |
| 单一规范化函数 | Go `organization.NormalizeHODStaffCode`；`validatePersonnelRow`同时服务上传preview与`import-review`。Web镜像`web/src/hodStaffCode.ts`，用于预览展示及提交前再规范化，二者用相同用例表测试 |
| 提取后校验 | 提取结果再经`NormalizeStaffCode`；提取发生时返回`hod_staff_code_extracted` warning；`-姓名`（前缀为空）阻断为`invalid_staff_code`，不静默丢弃主管 |
| HOD列长度 | 原始值上限64→320字节以容纳`工号-姓名`；提取后工号仍≤64字节 |
| 自我汇报 | 新错误码`manager_self_reference`；自环不再重复报`manager_cycle` |
| 现有员工校验 | 新增只读`WorkforceReader.StaffCodeExists`（`employee_business_identifier`按keyed lookup digest）；不在批次也不在库中报`manager_not_found`。只读、无写入；提交时仍按入职日重新核对主管有效性（既有行为） |
| 提交架构 | 新增`employees/import-commit`：在一个事务中复用OP-ORG-05创建与OP-ORG-10关系写入；整批幂等回执。Pass 1全部员工主体/基础事实，Pass 2统一绑定主管；任一步失败整批回滚 |

## 3. 非目标

- 不修改Staff Code自身列的校验（含`-`的既有Staff Code保持可用）。
- 不修改既有单人创建API，不新增migration；整批提交采用新增API。
- 不对主管做模糊匹配或姓名反查。

## 7. 门禁可运行性修复

- 未修改的`3e88c61`同样复现race下SQLite启动15秒超时。CPU采样定位到反复真实构造SQLite参考schema。
- 只缓存从本程序冻结migration生成的、按schema版本区分的SQLite参考定义；每次校验仍读取被检查数据库的实际catalog和外键状态。
- 测试fixture复用进程内缓存的空schema字节，复制后仍执行真实Migrate/CheckSchema；每个fixture的业务数据与安全材料独立创建，永久迁移测试继续执行真实DDL。
- API启动smoke编译并运行实际程序，观察TLS/keyd配置接受与拒绝行为；业务service/API并发路径仍由完整race套件验证。

- 最终全仓race揭示既有OIDC并发回调偶发零会话：SQLite身份事务先读mode再取writer，在WAL下与拒绝审计写竞争会产生读快照升级失败。改为先取得SQLite mode写锁再读mode，保持mode→org→subject顺序；既有8路真实回调回归增加共同开始barrier和结果诊断，未削弱“恰好一个会话”的断言。
