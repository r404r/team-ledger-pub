# PLAN · DEV-045 · 人员XLSX日期兼容与错误透传修复

- 日期：2026-10-16
- 状态：已完成
- 用户现象：上传人员模板后页面只显示“服务暂时不可用”，未显示工作表、单元格和具体原因；既有资料中的日期可能是多种文本样式。

## 根因

1. 服务端对行级错误返回HTTP 200 preview。若所有入职日均不符合严格`YYYY-MM-DD`，目录解析会跳过这些行，因此响应省略`catalog_revision/graph_revision`。
2. 页面无条件要求两个revision存在，把这份合法的错误preview误判为503，于是丢弃`Employees!单元格`错误并显示通用“服务暂时不可用”。
3. parser只接受规范ISO日期；旧Excel常见的`7/3/2023`等文本日期没有在进入业务校验前规范化。

## 日期契约

日期单元格仍必须是文本；公式和Excel数值日期仍不猜测、不转换。接受以下无时区、四位年份文本并统一输出`YYYY-MM-DD`：

- 年在前：`YYYY-MM-DD`、`YYYY/M/D`、`YYYY.M.D`、`YYYY年M月D日`，月日可一位或两位。
- 年在后：`M/D/YYYY`、`M-D-YYYY`、`M.D.YYYY`；固定按月/日/年解释，不接受含义不明的日/月/年。
- 拒绝两位年份、时间、时区、混合分隔符和不存在的日期。

错误固定到实际字段：无法识别的入职日为`Employees!J行/invalid_date`，无法识别的退职日为`Employees!O行/invalid_date`，退职日不晚于入职日为`Employees!O行/departure_not_after_hire`。服务端5xx无法安全定位单元格时，页面至少显示request ID供日志核对，不伪造cell。

## 不变安全边界

- 不解析公式，不读取外部关系，不执行宏。
- 不把Excel serial number按1900/1904系统猜成日期；非文本日期继续返回`text_required`。
- 错误响应和日志不包含单元格内容、姓名、Staff Code或其他PII。
- 有任何preview错误时禁止“确认并批量创建”。
