# PLAN · DEV-029 · 既有环境迁移基线

- 日期：2026-10-15
- 状态：规则固定与验证完成，待本task commit/push
- 类型：开发与部署规则变更；本task不修改数据库schema或运行代码
- 目标：从本通知起，所有未来数据库变更必须保护既有环境数据，并提供SQLite/PostgreSQL可执行前向迁移；不得继续假定空库安装或重建数据。
- 关联：F-DB-001、`docs/DEVELOPMENT_RULES.md`、`docs/TECHNICAL_SPEC.md`。

## 已确认决定

1. 用户已通知后续必须考虑既有环境migration；该通知终止“未来schema可继续只改clean baseline”的开发豁免。
2. 当前v12源码baseline及已部署环境中的实际`schema_version`、checksum、应用镜像commit共同构成后续迁移输入。不得假定部署环境恰好等于仓库HEAD。
3. v1-v11仍是通知前已明确不支持的历史schema；本决定不追溯承诺把v1-v11升级到v12。
4. 下一项影响schema、持久化格式、密文AAD、索引key版本或不可变事实解释的task，在设计前必须只读采集目标环境版本/checksum并登记支持的source matrix。

## 后续schema task硬门禁

- 已发布migration和当前冻结的v12 baseline bytes/checksum不得重写；新变化使用新schema版本和两种方言的前向migration。
- 先备份并验证恢复路径，再停写/迁移；失败不得自动清空、fallback空库或以重新导入替代原子升级。
- SQLite与PostgreSQL分别用带合成历史数据的前一支持版本执行迁移、中断/重启、重复运行和应用切换验证。
- 核对行数之外，还必须核对对象owner/FK、有效期、金额、revision、receipt、grant、审计引用、密文及key metadata；必要时执行获准合成解密和真实API/UI smoke。
- 若无法取得某个已部署版本或恢复前置，task保持阻塞并提供安全停留版本；不得宣称完成。
