# PLAN · DEV-028 · 全局查看日期与员工操作体验

- 日期：2026-10-15
- 状态：进行中
- 目标：将`as_of`收敛为顶部全局“查看日期”并默认集团当前业务日；把员工目录改造成可理解、可查询、可分页的员工一览；在人员创建流程补齐Staff Code与直属主管。
- 关联：F-ORG-001、P-ORG-02、P-ORG-03、OP-ORG-04/05/06/10。

## 已确认业务决定

1. `as_of`是全局查看日期，默认当天；它只决定有效期事实投影，不改变当前授权判断。
2. 员工目录必须提供查询条件、全量获准员工结果一览和分页；不得暴露未授权总数。
3. 人员录入必须包含全集团唯一、允许复用本人旧号的Staff Code，以及单一直属主管选择；直属主管/HOD读取同一administrative reporting事实。
4. 系统尚未进入重要环境，本task不设计既存数据merge或兼容迁移。

## 设计决定

1. `/session`返回由组织IANA时区计算的`business_date`；认证壳层以其初始化内存中的全局查看日期。日期不写浏览器持久存储，切换主导航时保留；只有单一合法`as_of`的受控深链接可恢复其历史查看日期，其余重新登录或加载回到服务端当天。
2. 顶部只显示业务名称“查看日期”，不向普通用户暴露`as_of`；相关页面使用同一日期并在改变时重新读取，不允许该日期恢复历史权限。
3. 员工目录继续使用现有OP-ORG-04安全游标：scope先于分页，不返回未授权总数；前端增加清晰筛选、空状态、表格/移动列表、上一页/下一页和当前页提示。
4. 姓名、Staff Code、联系方式和职位正文属于受保护人员资料。目录在操作者具有PII读取能力时请求并显示；无权时只显示安全ID和组织metadata，并明确说明，不再使用“请求PII资料”技术开关。
5. “图版本”是服务端用于并发一致性与cursor绑定的组织结构revision，不作为普通目录主内容；移入辅助说明。
6. 员工详情链接通过应用级导航进入并使用全局查看日期，必须真实读取并显示该员工详情。
7. 创建页面通过扩展OP-ORG-05一次提交profile/lifecycle、必填Staff Code及可选直属主管；服务端复用canonical workforce校验和写入，在同一graph guard事务写员工、identifier、administrative reporting、revisions、receipt及audit。任一冲突、无效主管或权限失败整笔回滚；成功receipt携带profile/workforce/graph revisions，UI重读权威详情。

## 验收边界

- 正常：登录后顶部日期等于服务端组织业务日；切换日期后人员资料、组织树、员工目录和薪资现状读取同一日期。
- 边界：跨UTC日但未跨组织本地日时仍使用组织本地日期；无效日期不触发业务请求；权限判断日仍由服务端独立捕获。
- 目录：空筛选查询全部获准员工；姓名/Staff Code筛选仅在当前PII权限范围执行；每页1..100；下一页与上一页不混页；filter/date变化回第一页。
- 详情：目录点击员工后呈现该员工获准资料，不出现空白页或旧员工内容。
- 创建：Staff Code冲突、无效主管、跨组织主管、缺写权限、revision冲突均明确失败；不得显示虚假的整体成功；成功后重读可见工号与直属主管。
- 安全：不返回未授权总数；姓名查询不进入URL/history/storage/log；日期不能恢复历史授权；无PII不解密或显示PII正文。
- 交付：每个T1/T2/T3完成后分别commit并push至私有`origin/main`和公开`pub-origin/main`；最终文档/审查task同样commit并双push。
