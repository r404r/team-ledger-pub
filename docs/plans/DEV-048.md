# PLAN · DEV-048 · 人员导入可选字段与目录适配

- 日期：2026-10-16
- 状态：T1–T6完成；全量回归发现的既有调薪日期断言见验证记录
- 目标：旧Excel中的可读取员工资料先完整进入可编辑预览；可选任职字段缺失不阻断；未知组织/职系/职级不静默猜测，而是在同一导入台显式映射或创建后重新校验。
- 既有环境：复用现有目录、员工与历史事实；不清库、不覆盖既有目录；本任务不需要schema migration。

## 1. 调查结论

1. `education_level`、`position`、`job_family_code`、`career_level_code`当前在导入边界被错误地当成全部必填；canonical model实际允许员工没有学历记录，且`job_assignment`的职系、职级和职位均可空。
2. Branch、Business Group、Division、Department是初始employment/job assignment的必要目录；未知值不能直接写员工事实。现有preview只报`unknown_catalog_code`，没有返回可选目录，也没有在导入台提供映射/显式创建路径。
3. 当前唯一label匹配区分大小写且不清理安全的首尾空白，导致旧Excel中轻微格式差异产生不必要错误。
4. 自动把每个未知字符串写成永久目录会把拼写错误固化为主数据。安全兼容边界必须是：值保留、可编辑、唯一匹配可规范化、永久目录新增必须由操作者明确确认。

## 2. 兼容契约

### 2.1 字段必填性

| 字段 | 导入规则 | 创建结果 |
| --- | --- | --- |
| Staff Code、至少一个姓名、Location、Branch、BG、Division、Department、入职日 | 必填并阻断错误 | 写入初始身份、employment和department assignment |
| 学历 | 可空；非空时须映射org学历目录 | 空值不创建education事实 |
| 职位 | 可空；非空时执行长度/UTF-8校验 | 空值不写position payload |
| Job Family、Career Level | 可空；非空时须映射目录 | 空值在job assignment中保持NULL |
| 退职日、HOD、联系方式、摘要 | 沿用可选规则 | 仅有值时写入对应事实/密文 |

### 2.2 目录解析

- 先按code精确匹配，再按去除首尾空白且不区分ASCII大小写的唯一code/label匹配；规范化时逐格warning。
- 重名、跨层级冲突、无效生命周期不猜测，继续阻断。
- preview返回当前入职日可用的Branch/BG/Division/Department/Job Family/Career Level候选，页面对每个目录字段提供可搜索建议。
- 未知目录按“类型＋值”聚合。页面允许将它改为已有code，或显式创建永久目录；创建前展示code、显示名、生效日和职级rank。BG → Division → Department父链从同一文件推导；同一子节点出现多个上级时阻断，不猜测。
- preview、映射和编辑本身不写数据库；只有操作者点击确认新增目录才调用既有OP-ORG-09，保留CAS、receipt和audit。

### 2.3 失败可诊断性

- 每条错误继续显示`Employees!Cell · field · 原因`。
- 可选空值不产生错误；未知必填目录明确提示“选择已有目录或展开目录适配”。
- 目录创建409时不重放新命令，要求重新校验；网络结果不确定时保留当前预览并要求显式重试/核对，不能把目录或员工显示为已创建。

## 4. 不做的危险兼容

- 不为未知目录静默自动建档。
- 不用模糊相似度把员工绑定到可能错误的Branch/部门/职级。
- 不用空字符串或虚构ID伪造学历、职系、职级或职位事实。
- 不覆盖、结束或重命名既有目录；目录冲突必须重新校验后由操作者处理。
