# PLAN · DEV-043 · Staff关联账号与默认本人/直属下属权限

- 日期：2026-10-16
- 状态：T1–T5全部完成
- 用户决定：创建本地用户时明确选择“Staff关联账号”或“非关联账号”；Staff关联账号默认可查看本人及名下员工资料、面谈信息，并可新建面谈。

## 1. 业务口径

### 1.1 账号类型

| 类型 | 创建输入 | 结果 |
| --- | --- | --- |
| `standalone` | 登录账号、初始密码 | 不绑定员工；不增加任何业务访问权 |
| `staff` | 登录账号、初始密码、精确Staff Code | 在同一事务中把新subject绑定到唯一employee，并启用`staff_default.v1` |

- `account_type`必须显式传入；不根据用户名、姓名或邮箱猜测。
- Staff Code按既有NFC/大小写/前导零规则精确匹配；必须在创建日对应一个当前有效employee。不存在、已绑定或匹配不唯一时整笔拒绝。
- 一个employee最多绑定一个subject；沿用`subject_employee`唯一约束。账号、凭证、绑定、默认政策、receipt与审计同事务提交。
- API/list返回`account_type`和Staff关联的`employee_id`；不在安全日志记录Staff Code、姓名或初始密码。

### 1.2 默认访问边界

“名下员工”固定为**当前有效、administrative reporting line的一层直属下属**；不递归到下属的下属。每次请求根据查看日期/组织时区和当前关系事实重新计算，不在创建账号时复制静态员工清单。

| 对象 | 可做 | 明确不做 |
| --- | --- | --- |
| 本人 | 读取员工metadata及PII；读取面谈metadata；新建面谈 | 修改员工资料、读取面谈笔记/行动/评估、薪酬、导出 |
| 一层直属下属 | 同上 | 跨层、已结束/被替换关系、其他员工 |
| 非关联账号 | 无默认业务权限 | 不根据部门、HOD文字或用户名自动授权 |

“新建面谈”仅为OP-INT-02创建路径的默认资格，不等同于通用`interview.write` grant；取消、改期、参与者变更及正文写入继续要求既有明确授权。默认政策不出现在可委派authority矩阵，也不能绕过MFA、session/epoch、对象owner和审计复核。

## 2. 技术设计

分配schema v17：

- 新增immutable `staff_account_access(org_id, subject_id, employee_id, policy_version, created_by, created_at)`；`policy_version='staff_default.v1'`。
- 行同时外键绑定`local_account(org_id,subject_id)`、`subject_employee(org_id,subject_id,employee_id)`和创建者subject；一名员工保持唯一绑定。
- v16→v17 migration只建表并登记checksum；既有账号不推断、不自动绑定、不补默认权限。
- 创建命令的幂等摘要加入`account_type`及规范Staff Code；同key更换类型或Staff Code返回mismatch。
- `Security` snapshot只在当前subject存在`staff_default.v1`时加载本人及当前一层直属下属ID。员工目录把这些ID加入候选scope；员工详情、面谈列表/详情仍逐对象实时调用默认政策判断。
- OP-INT-02在常规`interview.write`授权之外接受`staff_default.v1`创建资格；其他面谈写操作不接受该默认政策。

## 4. 验收场景

1. 管理员创建`standalone`账号：首次改密/TOTP流程不变；没有默认员工或面谈权限。
2. 管理员以精确Staff Code创建`staff`账号：用户列表显示关联employee；同一员工再次绑定整笔409且无半成品账号。
3. Staff账号可在员工目录看到本人和当前一层直属下属，可打开其完整资料；看不到同事、上级、二层下属。
4. 新增/结束直属关系后，不重建账号即可在下一次请求中获得/失去对应访问；旧cursor/旧epoch不能维持访问。
5. Staff账号可列出/查看上述员工的面谈metadata并新建面谈；读取shared/private/HR笔记、评估、行动、取消或其他写操作仍按原明确授权拒绝。
6. v16有数据数据库升级v17后既有账号全部保持非默认状态；不因既有`subject_employee`映射自动启用政策。
